Learning Objectives

After completing this lab, you will:

  • Write unit tests with Unity assertions: expected value, actual value, message
  • Know the behavior of the most common standard library functions: strlen, strcmp, atoi, atol, atof, sqrt, pow, floor, ceil, round, fmod, memcpy, memset, memcmp, strcpy, strcat, strchr, sprintf, qsort
  • Choose test cases: typical values, edge cases (empty, zero, negative, boundary) and invalid input
  • Compare integers, doubles, strings, raw memory and arrays with the right assertion
  • Understand why a test must be able to fail
  • Combine several functions in one test (round trips, properties that hold for many values)

How your tests are judged

  1. Your tests must pass. Every test function you write is run against the real standard library. A test that fails there is wrong.
  2. Your tests must be able to fail. The instructor also runs your tests against copies of the standard library that contain deliberate bugs (for example a strlen that is one too long for the empty string, or a qsort that does not sort). A good test notices the bug and fails. A test such as TEST_ASSERT_EQUAL_INT_MESSAGE(1, 1, "ok") passes on everything, so it detects nothing — and it will be reported.

That is why every step lists the cases your test must cover: empty strings, negative numbers, values on the boundary, an unsorted array whose smallest element is last. The bugs hide exactly there.

Allowed assertions

All of them compare an expected value with the actual one (expected first!):

Assertion Use it for
TEST_ASSERT_EQUAL_INT_MESSAGE(expected, actual, "message") integers, characters, and conditions turned into 1 / 0
TEST_ASSERT_EQUAL_DOUBLE_MESSAGE(expected, actual, "message") double values (compared with a tiny tolerance)
TEST_ASSERT_EQUAL_STRING_MESSAGE(expected, actual, "message") strings
TEST_ASSERT_EQUAL_MEMORY_MESSAGE(expected, actual, number_of_bytes, "message") raw bytes
TEST_ASSERT_EQUAL_INT_ARRAY_MESSAGE(expected, actual, number_of_elements, "message") int arrays

Write a meaningful message: it is what you will read when the test fails.

Background

What a Unity test looks like

A test is a function without parameters and without a result. It passes when no assertion fails:

void test_strlen_basic(void)
{
    TEST_ASSERT_EQUAL_INT_MESSAGE(5, (int)strlen("hello"), "strlen(\"hello\") should be 5");
    TEST_ASSERT_EQUAL_INT_MESSAGE(1, (int)strlen("a"), "strlen(\"a\") should be 1");
}
  • The first argument is what you expect, the second is what the code actually returns. If you swap them, the failure message shows the wrong way round.
  • The first failing assertion stops the test. Put the simple cases first.
  • main.c runs the tests and prints one line per failure and a summary:
code.c:48:test_strlen_basic:FAIL: strlen("a") should be 1. Expected 1 Was 2
27 Tests 1 Failures 0 Ignored

Turning a condition into an assertion

Some results are not numbers you can predict. strcmp() promises only the sign of its result: negative, zero or positive. A comparison in C gives 1 when it is true and 0 when it is false, so you can assert it:

TEST_ASSERT_EQUAL_INT_MESSAGE(1, strcmp("apple", "banana") < 0, "\"apple\" should come first");

The same works for pointers (found == NULL) and for any other yes/no question.

Return types

Function Returns Assert with
strlen size_t cast to int: (int)strlen(s)
atoi int directly
atol long cast to int: (int)atol(s) — keep the values within ±2 billion (the automatic tests run in 32-bit mode where long has 32 bits)
atof, sqrt, pow, … double TEST_ASSERT_EQUAL_DOUBLE_MESSAGE, with 0.5, 3.0, …
sprintf int — the number of characters written directly

Doubles

Most decimal fractions cannot be stored exactly in binary, so doubles are never compared with ==. TEST_ASSERT_EQUAL_DOUBLE_MESSAGE allows a tiny relative error, so 1.4142135623730951 can be compared with sqrt(2.0). Use 2.0, not 2, for the arguments of math functions.

Edge cases and properties

A test with only “friendly” values passes on buggy code too. Think about where a function could go wrong:

Look for Example
empty input strlen(""), atoi("")
zero, one pow(5, 0), an array with one element
negative numbers floor(-2.1), round(-2.5)
the boundary "2147483647", memcmp that differs only in the last byte
input that is “almost” valid "12abc", " 42"
unchanged input strcat(buf, ""), qsort with count 0

A property is a statement that must be true for many values. In step 14 you check, with a loop, that ceil(x) - floor(x) is 1 for every non-integer x. One property over six values can say more than six separate examples.

Pre-filled buffers

If a test copies text into a buffer full of zeros, a function that forgets to write the terminator '\0' still looks correct — the zeros are already there. Fill the buffer with a visible character first:

char buf[20];
memset(buf, 'X', sizeof buf - 1);       /* 19 x 'X' ...                          */
buf[sizeof buf - 1] = '\0';             /* ... and a terminator at the very end  */
strcpy(buf, "abc");
TEST_ASSERT_EQUAL_STRING_MESSAGE("abc", buf, "...");   /* fails if the '\0' was not copied */

Always leave a terminator at the end of the pre-filled buffer, so that a failing assertion never reads past the array.

Testing qsort

qsort() needs a comparator. You write the missing ones as helpers (cmp_char, cmp_strlen, cmp_str); cmp_int is given:

int cmp_int(const void *a, const void *b)
{
    int x = *(const int *)a;
    int y = *(const int *)b;
    return (x > y) - (x < y);
}

An array of strings (char *) needs one more dereference than an array of int: the comparator receives a pointer to a char *.

A sort test must use unsorted input — a sorted array comes out sorted even if qsort does nothing. Also test an array whose smallest element is last: it only moves if every element is really compared.

qsort() is not stable (equal elements may swap places), so inputs for the string tests contain no ties.

Round trips

A round trip converts a value there and back and expects the original:

int  → sprintf("%d")  → text → atoi → the same int

If either function is wrong, the number that comes back differs. Use arrays of values and a loop.
