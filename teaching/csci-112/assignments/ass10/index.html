General rules

  1. A comparator never modifies the elements it compares and has no side effects.
  2. A comparator returns any negative number, zero, or any positive number. It does not have to return exactly -1 / 1. The tests only look at the sign.
  3. Functions taking pointers must survive NULL arguments exactly as described (no crash).
  4. A function that allocates memory must free everything it does not return. No leaks.
  5. In functions that work with void *, convert to unsigned char * before you do pointer arithmetic. Never rely on void * arithmetic (it is not standard C).
  6. Sizes and counts are size_t. The size of an element is always passed or computed with sizeof — never hard-coded.

Part 2 – Your own generic sort

# Function Key concept
9 void swap_elements(void *a, void *b, size_t size) swapping raw bytes
10 void bubble_sort(void *base, size_t count, size_t size, Comparator compare) a qsort() look-alike
11 bool is_sorted_array(const void *base, size_t count, size_t size, Comparator compare) checking an order
  1. swap_elements – Exchanges the contents of two blocks of size bytes, byte by byte (no malloc, no helper array). Does nothing if a or b is NULL, if both point to the same block, or if size is 0.
  2. bubble_sort – A generic bubble sort with the same parameters as qsort(): the array base has count elements, each size bytes long, ordered by compare. It must work for any element type.
    • Does nothing if base or compare is NULL, size is 0, or count < 2.
    • The address of element i is (unsigned char *)base + i * size.
    • Pass number k (k = 0, 1, 2, …) compares only the first count - 1 - k pairs of neighbours; the last k elements are already in place.
    • Two neighbours are swapped only when compare(left, right) > 0. Because equal elements are never swapped, the sort is stable.
    • The sort stops after a pass in which nothing was swapped.
    • Consequently an already sorted array needs exactly count - 1 comparisons, and a reversed array needs exactly count * (count - 1) / 2. The tests count the calls of your comparator.
  3. is_sorted_array – Returns true if compare(element i, element i + 1) <= 0 for every pair of neighbours. An array with fewer than 2 elements is sorted. Returns false if compare is NULL or size is 0, or if base is NULL while count >= 2.

Background

Function pointers as callbacks

You already passed a function to another function in apply_operation(arr, 4, add). Sorting works the same way: the sorting code does not know how to compare your data, so you hand it a comparator.

typedef int (*Comparator)(const void *a, const void *b);

Comparator is a name for “pointer to a function that takes two const void * and returns an int”. It is exactly the type that qsort() expects.

The comparator contract

A comparator receives pointers to two elements of the array (not the elements themselves) and returns:

Return value Meaning
negative *a must come before *b
0 they are equal (any order is fine)
positive *a must come after *b

Because the arguments are const void *, you must first cast them to the right pointer type, then dereference:

int compare_int_asc(const void *a, const void *b)
{
    int x = *(const int *)a;
    int y = *(const int *)b;
    return (x > y) - (x < y);
}

(x > y) - (x < y) works because a comparison gives 1 or 0: (5 > 3) - (5 < 3) is 1 - 0 = 1, (3 > 5) - (3 < 5) is 0 - 1 = -1, and equal values give 0 - 0 = 0.

Two classic comparator bugs

/* BUG 1: subtraction can overflow */
return x - y;                  /* INT_MAX - (-1) overflows: undefined behavior */

/* BUG 2: truncation to int */
return (int)(fx - fy);         /* 1.5f - 1.2f = 0.3, (int)0.3 = 0 -> "equal"! */

Descending order for free

You do not need a second implementation. Swapping the arguments reverses the order:

int compare_int_desc(const void *a, const void *b)
{
    return compare_int_asc(b, a);
}

qsort()

void qsort(void *base, size_t count, size_t size,
           int (*compare)(const void *, const void *));
Parameter Meaning
base pointer to the first element
count number of elements
size size of one element in bytes
compare your comparator 
int numbers[] = {5, 2, 9, 1};
qsort(numbers, 4, sizeof(int), compare_int_asc);

Use sizeof *arr (or sizeof(type)) for the element size — never a hard-coded number. A wrong size is the most common qsort() mistake: the array is sorted “in pieces” and the result looks random.

qsort() is not guaranteed to be stable: equal elements may end up in a different order than they had before sorting. Your bubble_sort is stable.

Two kinds of string arrays

char names[3][NAME_LEN] = {"pear", "apple", "fig"};     /* strings stored IN the array */
char *strs[3]           = {"pear", "apple", "fig"};     /* array of POINTERS to strings */
names (3 * NAME_LEN bytes):                strs (3 pointers):
┌──────────────────┐                       ┌─────┐      ┌───────┐
│ p e a r \0 ...   │ element 0             │  ───┼────► │ pear  │
├──────────────────┤                       ├─────┤      ├───────┤
│ a p p l e \0 ... │ element 1             │  ───┼────► │ apple │
├──────────────────┤                       ├─────┤      ├───────┤
│ f i g \0 ...     │ element 2             │  ───┼────► │ fig   │
└──────────────────┘                       └─────┘      └───────┘
element size = NAME_LEN                    element size = sizeof(char *)
comparator gets: a pointer to the          comparator gets: a pointer to the
first character (char *)                   pointer (char **)

So compare_str_asc is strcmp((const char *)a, (const char *)b), while compare_strptr_asc must first dereference: strcmp(*(const char * const *)a, *(const char * const *)b). Using the wrong one compiles, but crashes or sorts garbage.

Bubble sort

Bubble sort compares neighbours and swaps them when they are in the wrong order. After each pass the largest remaining element has “bubbled up” to its final place at the end.

{5, 2, 9, 1}   pass 0 (3 pairs):  5>2 swap -> 2 5 9 1 ; 5<9 ok ; 9>1 swap -> 2 5 1 9
               pass 1 (2 pairs):  2<5 ok ; 5>1 swap -> 2 1 5 9
               pass 2 (1 pair):   2>1 swap -> 1 2 5 9
               done: 3 + 2 + 1 = 6 comparisons
  • The last k elements are already in place after k passes, so pass k compares only count - 1 - k pairs.
  • If a whole pass makes no swap, the array is sorted and you can stop.
  • It needs about count²/2 comparisons, so it is slow for large arrays. We write it to understand sorting; in real programs use qsort().

A generic swap

You cannot write T tmp = *a; when you do not know T. Instead you swap bytes:

unsigned char *pa = a;
unsigned char *pb = b;
for (size_t i = 0; i < size; i++)
{
    unsigned char tmp = pa[i];
    pa[i] = pb[i];
    pb[i] = tmp;
}

The same trick gives you the address of element i of any array: (unsigned char *)base + i * size.

Why sort a copy?

qsort() sorts in place. A function that only wants to look at sorted data (a median, duplicates) must not reorder the caller’s array. So it copies first:

int *copy = malloc(count * sizeof *copy);
memcpy(copy, arr, count * sizeof *copy);
qsort(copy, count, sizeof *copy, compare_int_asc);
/* ... use copy ... */
free(copy);
