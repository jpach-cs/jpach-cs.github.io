What the output looks like

For the tree 10 (left 5 (left 3, right 7), right 20):

formatSideways()          formatLevelOrder()     formatDfs()
       --> 20             10                     10 5 3 7 20
--> 10                    5 20
              --> 7       3 7
       --> 5
              --> 3
  • Every line ends with '\n'. Values are separated by one space, with no space at the end of a line.
  • For an empty tree all three methods return "".
  • formatSideways is the tree turned 90 degrees to the left: the right subtree is above the node, the left subtree below it. A node at depth d is printed as d * indent spaces + "--> " + value + "\n".

Part 1 Methods — src/code.cpp

Method Description
formatSideways(int indent = 7) Throw std::invalid_argument if indent is negative. Otherwise create the result string and call sidewaysFrom
sidewaysFrom Recursive helper (given signature): first the right subtree, then the node, then the left subtree. Depth grows by one in every call
formatLevelOrder One line per level. Use std::queue<const TreeNode *>. At the start of a level, q.size() is the number of nodes on that level
formatDfs Preorder in one line. Use std::stack<const TreeNode *>. The stack is LIFO: push the right child first, then the left one

Build the text with std::format, std::to_string and +=:

out += std::format("{}--> {}\n", std::string(depth * indent, ' '), node->value);

Part 2 Methods — src/code.cpp

The file format

header:  the 4 bytes of kMagic ("BTR1"), then an std::int32_t with the number of nodes
body:    the tree in PREORDER. For every position:
           - a missing child:  ONE byte with the value 0
           - a node:           ONE byte with the value 1, then its value as std::int32_t,
                               then the whole left subtree, then the whole right subtree

The tree 1 (left child 2) is stored as these 21 bytes:

'B' 'T' 'R' '1' | 2 (int32) | 1 | 1 (int32) | 1 | 2 (int32) | 0 | 0 | 0

A tree with n nodes always occupies exactly 6n + 9 bytes. The file holds only the values and the shape of the tree: never a node, never a pointer. The numbers are written in the native byte order of the machine.

Methods

Method Description
save Open the file (std::ios::binary, an existing file is replaced), write kMagic, the count, then the body. Flush and check the stream. Throw TreeFileError if the file cannot be opened or the writing fails. An empty tree is valid. save does not change the tree
writeNode Recursive helper: writes one position (a 0 byte, or a 1 byte + value + left + right)
BinaryTree(const std::string &filename) The restoring constructor. Open the file, check the magic number and the count, read the body, check that exactly the announced number of nodes was read. Set rootPtr and count only at the very end
readNode Recursive helper: reads one position into slot (a reference to the pointer that must receive the new node). Check the stream after every read

When to throw TreeFileError

The constructor throws TreeFileError if:

  • the file cannot be opened (the message contains the file name),
  • the first 4 bytes are not kMagic,
  • the announced count is negative or larger than kMaxNodes,
  • the file ends too early (any read fails),
  • a position byte is neither 0 nor 1,
  • the body holds more nodes than announced, or fewer.

save throws TreeFileError if the file cannot be opened for writing (the message contains the file name) or if the writing fails.

An empty tree is not an error: it is saved and restored like any other tree. Use std::format for the messages, for example std::format("cannot open '{}' for reading", filename).

Notes

  • Write every field separately. out.write(reinterpret_cast<const char *>(&value), sizeof value) writes the bytes of one std::int32_t. Never write a whole TreeNode: it holds pointers, and a pointer is meaningless in the next run of a program.
  • The file does not contain parent pointers. readNode creates the nodes, so it must set parentPtr of every new node (the node that is currently reading it is the parent).
  • Reading uses a slot: readNode(in, parent, slot, ...) stores the new node in slot. At the start slot is the root variable, later it is node->leftPtr or node->rightPtr of the parent.
  • Link the new node into the tree immediately after creating it and before reading its children. Then a half-built tree is always reachable from the root variable.
  • A constructor that throws never finishes: the destructor ~BinaryTree is not called. Everything created so far must be deleted by the constructor itself, so a bad file leaks nothing:
TreeNode *newRoot = nullptr;
std::int32_t nodesRead = 0;
try
{
    readNode(in, nullptr, newRoot, nodesRead, announced);
    // ... check nodesRead against announced, throw if they differ
}
catch (...)
{
    destroy(newRoot);      // delete the half-built tree
    throw;                 // and report the problem to the caller
}
  • The reader refuses a header with more than kMaxNodes nodes, so a corrupt file cannot make your program allocate without limit.

Rules

  • Do not modify include/code.hpp or any function signature.
  • All code must compile under C++20 (-std=c++20).
  • In Part 1 and Part 2 do not use <<, >>, std::cout, printf or string streams. Build text with std::format, std::to_string and +=; read and write files with write() and read(). CI checks it (check_rules.sh).
  • formatLevelOrder must use std::queue and formatDfs must use std::stack (no recursion in them).
  • Open files with std::ios::binary. Do not use the C file API (fopen, fwrite, fread).
  • Throw exceptions only where this description says so. Do not throw for an empty tree.
  • Check the state of the stream after reading and after writing.
  • A bad file must not leak memory: the instructor tests count every allocation.
  • Remove the temporary files that your tests create.
  • CI builds with AddressSanitizer: memory leaks, double delete and use-after-free fail the build.
  • CI runs your tests.cpp together with the instructor tests — both must pass.
